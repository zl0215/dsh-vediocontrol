# dsh-push-to-talk — 按住说话

给 DeepSeek Harness 输入框加一个「按住说话」麦克风和一个**单键按住**快捷键：**按住录音，松开自动识别并发送**。

它复用本机已有的语音识别后端（语音输入插件包里的 `speechToText` 服务：SenseVoice 本地模型或云端服务），不重新下载模型，也不新增识别通道。

另外提供一个**截图并发送**快捷键（默认 **F3**）：按一下截取整个屏幕，直接作为图片消息发送到当前会话，不会把 DSH 切到前台。

## 安装

从 GitHub 源码安装（当前可用）：

```
dsh plugin --profile web add github:zl0215/dsh-vediocontrol
```

等价的完整 Git 地址写法：

```
dsh plugin --profile web add git+https://github.com/zl0215/dsh-vediocontrol.git
```

发布到 npm 之后（暂未发布）也可以：

```
dsh plugin --profile web add dsh-push-to-talk
```

也可以在 DSH 的 **插件 → 安装** 页面填入包名或 Git 地址安装。安装后本 bundle 会：

- 停用内置的点击式语音前端 `ui-voice-input`，改为按住说话按钮 + 单键快捷键；
- 在 Windows 上按需启动一个本机辅助进程来监听全局按键（不联网）。

前置条件：已启用 `@deepseek-ai/dsh-experimental-voice-input-bundle`（提供 `speechToText` 与 SenseVoice 模型）；首次使用需在页面里允许一次麦克风权限。

## 用法

- **麦克风**：输入框右侧、发送按钮之前。按住开始录音，波形与计时显示在输入框下方，松开即识别并发送。
- **快捷键**：默认 **F2**（单个按键）。在任意位置按住 F2 说话，松开即识别并发送；也可以在输入框里按住它。
- **取消**：上滑后松开、按 **Esc**，或按住快捷键时再按其它字符键，都会取消本次录音。
- 按下不足 350ms 视为误触，不会识别；没识别到语音也不会发送。
- 最长单次录音 120 秒（与语音服务默认上限一致）。
- **截图（F3）**：按一下截取整个屏幕并直接发送到当前会话；在其它软件里也能用（需要全局快捷键已启用）。

## 修改快捷键

**设置 → 通用 → 「按住说话快捷键」**：

- 点「修改」，再按下一个按键即可绑定。只接受**非字符按键**，避免和打字冲突：
  `F1`–`F12`、左/右 `Ctrl`、左/右 `Alt`、左/右 `Shift`。
- 「恢复默认」回到 `F2`。
- 绑定保存在浏览器本地（`localStorage`），换页面/重启后仍生效。

**设置 → 通用 → 「截图并发送」**：点键名可以改截图快捷键（默认 `F3`，同样只接受功能键/修饰键）；旁边的开关可以整机关闭这个功能。截图键不能和按住说话键相同。

同一页面还有 **「麦克风常驻」** 开关：打开后麦克风保持待命，按下零等待（系统麦克风指示会一直亮着）；关闭时只在每次识别后热连接 2 分钟。第一次识别成功后会弹一次「开启零等待」的提示条，点一下即可打开。

> 之所以限制为功能键/修饰键：单个字符键（如 V）一旦绑定，就必须在每次输入该字符时让路，会破坏正常打字。

## 会话窗口里的快捷设置

输入框右侧、麦克风按钮旁边有一个**齿轮按钮**，点开后会在输入框上方展开一行快捷设置，不需要再进设置页：

- **回复同步到微信**：开/关（还需要先在设置 → 微信 绑定微信插件）；
- **语音识别服务**：下拉选择（例如本机 SenseVoice / 云端服务）；
- **识别语言**：下拉选择（自动识别 / 中文 / English 等，跟随所选服务支持的语言）；
- **按住说话键**：下拉直接改（F1–F12 或左右 Ctrl/Alt/Shift，避免和打字冲突的限制不变）；
- **截图键**：下拉直接改。

点右侧「×」收起。修改会立即保存：语音服务/语言通过 Host 的 `speechToText.configure` 持久化，按键与开关存在浏览器本地，重启后仍生效。原来的设置页入口继续保留，两边改的是同一份配置。

## 全局快捷键（离开 DSH 也能用）

打开 **设置 → 通用 → 「全局快捷键（其它软件中也能用）」**（默认开启）后：

- 本插件会启动一个本机 PowerShell 辅助进程（`hotkey.ps1`），安装 Windows 低级键盘钩子，**只监听你绑定的按住说话键和截图键**，不联网、不记录输入，也不拦截按键（其它软件照常收到这些键）。
- 之后即使你正在用别的软件、DSH 窗口在后台，**按住 F2 说话 → 松开**，识别结果会自动发送到 DSH 当前会话，由助手继续处理。
- 更换快捷键后会自动重启辅助进程、改为监听新键；关闭开关即停止辅助进程。
- 「麦克风常驻」建议同时打开：这样在其它软件里按下按键也是零等待；否则每次冷按仍会等设备打开。
- 第一次使用仍需在 DSH 页面里允许一次麦克风权限。

注意：

- 目前仅支持 Windows。
- DSH 窗口**不要最小化**（可以放在其它窗口后面）；最小化时浏览器会节流页面，按键与界面更新可能延迟。
- 如果任务需要工具调用审批，DSH 会停在审批提示上等你回到窗口确认；想让它全程自动执行，需要在设置里使用更宽松的权限预设。

辅助进程的约定（`hotkey.ps1`）：

- 由 Host 以 `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File hotkey.ps1` 启动，只设置环境变量 `DSH_PTT_KEY`（按住说话键）与 `DSH_PTT_SHOT_KEY`（截图键，未开启时为空）。
- stdout 每行一个事件、立即刷新：`ready`（钩子装好）、`down main` / `up main`（按住说话键）、`down shot` / `up shot`（截图键）、`error <原因>`；自动重复不会重复上报 `down`。
- 安装低级键盘钩子（`SetWindowsHookEx(WH_KEYBOARD_LL)`）后始终把按键转发给系统，**不吞键**。
- 不需要管理员权限、不联网、不写磁盘；准备就绪约 0.7 秒（运行时编译内嵌 C#）。
- 已知边界：收不到发往“以管理员运行”窗口的按键；UAC 提示/锁屏期间不产生事件；注入的按键也会被识别（便于自动化测试）。

## 截图并发送（F3）

按一下截图键（默认 **F3**）即可：

- 由 Host 侧的本机辅助进程（`screenshot.ps1`）截取**整个虚拟桌面**（所有显示器，超宽时缩放到不超过 1920px 宽），生成一张临时 PNG；
- 图片通过回环接口交回页面，页面把它作为图片附件插入当前会话的输入框并**立即发送**，不需要 DSH 在前台，也不会切换窗口；
- 截图文件读取后立即删除，不在磁盘留存。

说明：

- 需要当前有一个打开的会话（有输入框）；没有会话时会提示，不会发送。
- 在其它软件中按 F3 依赖「全局快捷键」已启用；在 DSH 页面内按 F3 也可以（会阻止浏览器默认的“查找下一个”）。
- 截图会作为普通图片消息进入当前会话，并和普通附件一样被模型看到；涉及敏感画面时请先关闭此功能（设置里的开关）或按 Esc 前不要按 F3。
- 目前只支持整屏截图，没有区域框选/单窗口截图。

## 麦克风权限与延迟

**为什么会弹「请允许使用麦克风」**：录音必须由浏览器调用系统麦克风，第一次在某个页面（来源）上使用时会询问授权。授权按「来源」记录，DSH 桌面端的本地页面地址带端口；如果两次启动之间端口不同，浏览器会把它当成新站点再问一次。点一次「允许」即可，同一来源之后不再询问。这是浏览器/Electron 层的行为，插件无法绕过。

**第一次按住可能“白按”一次**：授权弹窗期间还没开始录音。授权完成后如果已经松手，插件会提示「麦克风已授权。请再次按住说话」；如果一直按着，授权通过后会直接开始录音。

**按下 → 开始聆听之间为什么有延迟，以及怎么减少**：

延迟来自浏览器/系统打开麦克风设备本身（冷启动约 0.1–0.4 秒，蓝牙耳机可能 1 秒以上）。

- **鼠标点麦克风**：授权后，鼠标移到按钮上时插件已经提前打开设备，所以点下去基本没有延迟。
- **快捷键（F2）**：没有“悬停”这种提前信号，按下那一刻才开始打开设备，所以会看到这段冷启动延迟。
- 每次识别成功后麦克风会保持热连接 **2 分钟**，这段时间内再按快捷键几乎立即开始录音——也就是“说一句 → 等一下 → 再说一句”的第二次通常已经很快；只有中间隔了很久或第一次按会慢。
- **要彻底消除**：开启「麦克风常驻」，麦克风一直待命。第一次识别成功发送后，输入框下方会出现一次提示条「开启零等待」，点一下即可；也可以在 **设置 → 通用 → 「麦克风常驻」** 打开。代价是系统麦克风指示会持续亮着。

其他优化：全页面共用一个 16 kHz AudioContext，按下与松开两端都省掉创建/重采样开销；模型处于 `standby` 时会在按下瞬间顺便预加载；状态条会区分「正在打开麦克风…」和「请允许使用麦克风…」，看到「正在聆听」再开口可以避免第一个字被剪掉。

**松开 → 文字发出**：录音收尾 + 本机识别通常 0.2–0.6 秒（SenseVoice 对 1 秒音频约几十毫秒）。

**如果提示「语音识别失败：Could not start audio source」**：这是浏览器打不开麦克风设备（`NotReadableError`），常见原因有：

- 会议/录音软件正占用麦克风（例如腾讯会议、OBS、录音机）；
- Windows 隐私设置里禁用了麦克风访问（设置 → 隐私和安全性 → 麦克风 → 允许桌面应用访问）；
- 蓝牙耳机刚切换了音频配置，设备短暂不可用。

插件在打开设备失败时会**自动重试一次**；仍失败时提示条里会出现「重试」按钮，关闭占用程序后点一下即可，不必重新按键。

## 依赖

- 已启用 `@deepseek-ai/dsh-experimental-voice-input-bundle` 提供的 Host 侧语音识别行（`speech-to-text`、`speech-to-text-sensevoice`、`api-speech-to-text`）。本插件只替换前端交互，不替换后端。
- 识别模型已准备好。若尚未准备，输入框下方会提示「下载并准备」，本插件可以直接触发下载并显示进度。
- 浏览器麦克风权限（本机回环地址即可，无需 HTTPS）。

## 发送行为

识别完成后，文字会插入到按住时记录的光标位置，然后立即提交发送（`inputActions.submit()`）：

- 输入框里原本已经输入的草稿会连同识别结果一起发送。
- 如果录音期间草稿被改动，插入会失败；此时结果会保留在输入框下方，提供「插入并发送 / 丢弃」。
- 未识别到语音、录音太短、识别失败时只提示，不会发送。

## 与内置语音插件的关系

本 bundle 的 patch 在启用时会把内置语音前端 `ui-voice-input`（点击开始、再点停止的麦克风）关掉，改用按住说话按钮与快捷键，避免出现两个麦克风。停用或卸载本插件后，内置麦克风自动恢复。已经被语音插件保存的「识别服务 / 识别语言」偏好继续生效；由于内置前端被停用，语音插件详情页里的识别偏好与设备选择面板不再显示（模型已就绪时通常无需再改）。如需改回原前端，停用本插件即可。

## 实验功能：回复浮窗（默认关闭）

这是附带的实验性功能，不属于主要能力，**默认关闭**，只在 Windows 上可用。

- **开关路径**：设置 → 通用 → 「回复浮窗（实验）」。
- 开启后：用全局快捷键提问时，回答会**边生成边显示**（流式刷新）；可点右上角「×」关闭，回答结束后约 10 秒自动消失。
- **外观设置**（同一设置行内）：背景不透明度（10%–100%）、字体、字号；修改后下一次显示生效。
- 背景 100%（不透明）时面板可以被屏幕共享/录屏排除；低于 100% 时是半透明窗口，会看到后面的桌面。
- 关闭后：不再启动浮窗辅助进程，插件只做语音输入，不显示任何浮窗。
- 实现：可选的 `overlay.ps1` 辅助进程（本机 PowerShell/WPF，通过 stdin 接收流式与最终文字）。

## 回复同步到微信（实验，默认关闭）

如果你装了微信插件（`dsh-wechat-plugin`）并绑定了手机，可以把这个开关打开：

- **开关路径**：设置 → 通用 → 「回复同步到微信」。
- **行为**：只对**通过 F2 语音或 F3 截图触发的那一轮**生效——该轮结束时，把最终回复（一轮合并成一条，最多 4000 字）通过微信机器人发到手机；不会把电脑上其它对话的回复也推过去。
- **不会重复**：如果这个会话本身就是从微信发起的（已绑定微信对话），微信插件本来就会把回复发回微信，本插件会跳过。
- **实现**：Host 直接调用微信插件自带的 `dsh-wechat-send` 命令模块（与插件共用回复窗口计数；窗口用完时消息会排队，不会丢）。
- **前置条件**：安装并启用 `dsh-wechat-plugin`，在 **设置 → 微信** 扫码登录，并用手机给机器人发一条消息建立绑定。
- **注意**：回复内容会离开这台电脑进入微信，手机通知可能被旁人看到；微信一个回复窗口最多连发 10 条，超出的排队等下次互动；电脑需保持运行。

## 本机接口

Host 侧只注册一个仅回环可访问的 JSON 接口（`127.0.0.1` / `::1`），其它地址一律 403：

```
GET  /push-to-talk/api/status          识别服务、选中服务商、准备进度、录音上限
POST /push-to-talk/api/transcribe      { audioBase64 } → { text }（16 kHz 单声道 PCM16 WAV）
POST /push-to-talk/api/prepare         准备模型（可选下载源）
POST /push-to-talk/api/hotkey/bind     启动/停止全局按键辅助进程（{ enabled, code, shotCode }）
POST /push-to-talk/api/screenshot/capture 截取整个屏幕 → { imageBase64, mediaType, width, height, bytes }（仅 Windows）
GET  /push-to-talk/api/hotkey/state    辅助进程状态
GET  /push-to-talk/api/hotkey/poll     长轮询按键 down/up 事件（?since=N）
POST /push-to-talk/api/overlay/arm     回复浮窗（实验）：开始监听某会话这一次提问的回复（流式）
POST /push-to-talk/api/overlay/config  回复浮窗（实验）：设置背景不透明度/字体/字号（{ opacity, fontFamily, fontSize }）
POST /push-to-talk/api/wechat/config   回复同步到微信（实验）：{ enabled }
GET  /push-to-talk/api/wechat/state    回复同步到微信（实验）：状态、是否可用、上次错误
POST /push-to-talk/api/speech/config   会话快捷设置：切换识别服务/语言（{ providerId, language }），返回新的服务快照
POST /push-to-talk/api/overlay/show    回复浮窗（实验）：直接显示一段文字（调试用）
POST /push-to-talk/api/overlay/hide    回复浮窗（实验）：收起浮窗
GET  /push-to-talk/api/overlay/state   回复浮窗（实验）：状态
```

录音数据只在本次请求内存在，不写入会话事件或附件。以上接口同样只接受本机回环访问。

## 已知限制

- 不提供输入设备选择器和识别语言选择器：使用系统默认麦克风与语音插件中已保存的服务/语言（默认自动识别）。
- 页面内快捷键只在聊天输入框存在时生效（新建会话/设置页等无输入框的页面不会触发）；全局快捷键需要当前会话的输入框存在，DSH 窗口运行中即可。
- 全局快捷键仅支持 Windows，且会额外运行一个本机 PowerShell 辅助进程；DSH 窗口最小化时页面会被节流，建议保持窗口可见（可在其它窗口后面）。
- 页面内按住期间切换会话、页面隐藏或浏览器失焦会结束/取消本次录音；全局录音不受窗口失焦影响。
- 回复浮窗为实验功能，默认关闭，仅 Windows 可用。
- 截图功能仅 Windows 可用，且只有整屏截图；截图会作为图片消息进入会话，敏感画面请先关闭该功能。
- 若语音识别服务不可用（语音输入插件包被停用），按钮会以半透明提示，输入框下方给出说明。

## 文件

- `index.js` — Host 插件：注册回环 JSON 接口，桥接 `speechToText`；管理全局按键辅助进程，并（实验功能开启时）把回复送到浮窗。
- `hotkey.ps1` — Windows 辅助进程：低级键盘钩子，把按住说话键与截图键的按下/松开写到 stdout。
- `client.js` — 浏览器插件：按住手势与单键按住、全局按键事件订阅、录音与 16 kHz 重采样、识别状态条、设置行、插入并发送。
- `screenshot.ps1` — Windows 辅助进程：按需截取整个虚拟桌面并写出临时 PNG（最多缩放到 1920px 宽）。
- `overlay.ps1` — 实验功能：Windows WPF 流式浮窗（默认关闭；支持背景不透明度、字体、字号）。
- 微信同步（实验）：Host 通过 `dsh-wechat-plugin` 的 `dsh-wechat-send` 命令模块，把快捷键触发那一轮的最终回复发到已绑定的微信。

## 验证

已在当前 `desktop` 配置中验证：

- `node --check` 通过（`index.js`、`client.js`）。
- 离线冒烟测试通过（`node test/smoke-client.mjs`）：加载浏览器模块、执行 `apply()`、注册各入口、渲染组件、
  拦截默认 F2 按键、重新绑定按键并持久化、截图键改绑与截图请求、切换「麦克风常驻」「全局快捷键」「回复浮窗」并持久化，

- 全局按键辅助进程 `hotkey.ps1` 独立测试通过：18 个可绑定按键的 `ready/down main/up main`、非目标键不触发、
  长按自动重复只上报一次、20 秒存活与继续工作；`spawn → ready` 实测 0.65–1.13 秒。
- Host 端到端：`/hotkey/bind` 启动辅助进程并很快 ready；注入一次 F2 后 `/hotkey/poll` 返回 down/up；重复 bind 复用进程。

- 截图辅助进程实测：`ready` 约 0.6 秒；单次 `capture` 约 0.15 秒（1920×1080 PNG 约 430 KB）；Host `POST /screenshot/capture` 首次约 1.3 秒（含辅助进程启动），之后直接复用进程。
- 两键全局按键实测：`DSH_PTT_KEY=F2` + `DSH_PTT_SHOT_KEY=F3` 时注入 F2/F3 分别得到 `down main/up main` 与 `down shot/up shot`，其它键不触发；重复键/非法键以 `error` 退出。
- 回复浮窗（实验）探针测试通过：流式更新、最终显示、自动隐藏、再次显示、隐藏、退出正常（约 0.7–0.9 秒就绪）；
  不透明模式实测捕获排除 `affinity=0x11`，半透明模式（60%、宋体 22px）正常显示与更新。
